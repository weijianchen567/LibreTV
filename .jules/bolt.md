## 2025-02-18 - [Optimize Express Page Rendering with Bounded Maps, Async Files & Pre-calculated Hashes]
**Learning:** In a heavily trafficked Express app doing template rendering, using synchronous file system operations (`fs.readFileSync`) and calculating expensive crypto hashes for static config values dynamically for every request will completely block the Node.js event loop causing major latency spikes. Moreover, naively implementing dynamic page caching using `fs.watch` without properly closing file watchers on cache eviction or handling file deletion will leak file descriptors and crash the process over time.
**Action:** Always pre-calculate invariant static properties (like configured passwords) at startup using top-level `await`. Always use `fs.promises.readFile` for template loading to preserve event loop concurrency. When caching rendered pages, bound the cache size (e.g., max 100 entries) and explicitly clean up associated `fs.watch` instances on cache eviction (only if no other active keys reference the file path) or on `ENOENT` error.
