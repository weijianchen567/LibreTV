## 2024-11-20 - Caching Rendered Pages and Pre-calculating Hashes in Node.js
**Learning:** In a Node.js Express application, repeatedly performing synchronous file reads (`fs.readFileSync`) and CPU-bound operations like cryptographic hashing (`crypto.createHash`) within a request handler can block the event loop and severely impact performance under load. Furthermore, checking file stats asynchronously per request for cache validation introduces event loop overhead.
**Action:** When serving static files that require minimal dynamic injection (like replacing placeholders with hashes of static environment variables), pre-calculate the heavy CPU operations at application startup using top-level `await`. Use an in-memory `Map` to cache the processed content. For cache invalidation, use `fs.watch` to listen for file system events asynchronously instead of performing `fs.promises.stat` on every request. Use `fs.promises.readFile` to perform non-blocking file reads when the cache is empty.
