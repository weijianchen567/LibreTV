## 2024-10-07 - Server Performance: Avoid Synchronous File Reads in Request Handlers
**Learning:** Found that \`fs.readFileSync\` was being used in \`renderPage\` to serve \`index.html\` and \`player.html\` on every request. This is a significant bottleneck in Node.js, as synchronous file I/O blocks the entire event loop, preventing the server from handling concurrent requests efficiently. Furthermore, CPU-bound tasks like SHA-256 hashing for static passwords were being recalculated on every request.
**Action:** Always use asynchronous file operations (like \`fs.promises.readFile\`) for file serving or dynamic content loading inside request handlers. For configurations or values that do not change during runtime (like static passwords from env vars), pre-calculate hashes or heavy operations at startup using top-level await.
