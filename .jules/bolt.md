## 2025-05-18 - Avoid synchronous file reading and redundant hashing in request handlers
**Learning:** In a Node.js Express application handling static/template files (like `server.mjs`), using `fs.readFileSync` for page rendering and hashing static configuration passwords on every request unnecessarily blocks the event loop and wastes CPU cycles. This is particularly problematic in an application like `libretv` which acts as a proxy and search hub that can experience high concurrency. At the same time, we must avoid caching file contents in memory (e.g., using `Map`) to prevent memory leaks, DoS vulnerabilities, and breaking local dev watch tools like `nodemon`.
**Action:** Use asynchronous `fs.promises.readFile` for template reading to keep the event loop non-blocking. For static, globally configured values (like passwords loaded from env vars), pre-calculate hashes at server startup using top-level `await`. For dynamic requests that provide custom values, gracefully fall back to asynchronous hashing at request time.
