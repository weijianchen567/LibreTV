## 2024-05-24 - Node.js SSR Template Caching & Invalidation
**Learning:** In a basic Express setup serving dynamically injected HTML (like replacing password templates), `fs.readFileSync` on every request becomes a bottleneck under load. Using a fast in-memory `Map` as a template cache significantly reduces IO overhead. Furthermore, since template injection depends on both the file content AND environment/config variables (like `password`), the cache key MUST be composite (e.g. `path|password|adminpassword`) to avoid serving unauthorized/incorrect content if configs change dynamically. Lastly, using `fs.promises.stat` for `mtimeMs` checking provides an efficient and reliable cache invalidation strategy for local file edits without requiring watchers.
**Action:** When manually implementing SSR or template rendering in Node.js, always cache the results in memory. Ensure the cache key includes all variables that affect the output, and validate the cache against the file's `mtimeMs` to support hot-reloading without server restarts.
