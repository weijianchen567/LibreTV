## 2024-09-30 - [Performance Bottleneck: Synchronous File I/O and Redundant Hashing in Request Handlers]
**Learning:** Found a codebase-specific bottleneck in `server.mjs`. The `renderPage` function, which handles page renders for routes like `/`, `/player.html`, and `/s=keyword`, uses synchronous `fs.readFileSync`. This blocks the Node.js event loop on every request. Furthermore, SHA-256 hashes for static `PASSWORD` and `ADMINPASSWORD` from the config were being recalculated on every single render request, even though they are static.
**Action:** Replace `fs.readFileSync` with the asynchronous `fs.promises.readFile` to prevent blocking the event loop. Pre-calculate the SHA-256 hashes of the static passwords at startup (using top-level await in the ES module) and cache them, using the pre-calculated hashes in `renderPage` instead of recalculating on every request.
