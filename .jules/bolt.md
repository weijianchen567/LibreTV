## 2026-07-19 - Caching Rendered Files with Map and fs.watch in Node.js
**Learning:** In Node.js server applications, blocking the event loop on synchronous I/O or CPU-heavy tasks like `fs.readFileSync` and `crypto.createHash` for static assets on every request can cause severe performance bottlenecks under load. Moving static CPU work to initialization phases (like pre-calculating a static password hash) and using a bounded Map as an LRU cache significantly improves throughput. However, to keep the cache synchronized with file updates, `fs.watch` must be used. We must handle synchronous exceptions like `ENOENT` natively because if a file doesn't exist during startup, it can otherwise crash the initialization sequence.
**Action:** Always consider pre-calculating static configuration hashes during server boot. When utilizing in-memory caches, employ a bounded data structure (like Map with size limits) to prevent memory leaks and combine it with `fs.watch` wrapping a `try/catch` block for resilient cache invalidation.
