## 2024-05-30 - Caching Rendered Pages in Express App
**Learning:** The Express server was previously reading static HTML files synchronously (`fs.readFileSync`) and performing synchronous-like operations (SHA-256 hashing for passwords) on every request to `/` and `/player.html`. This blocked the Node.js event loop and caused unnecessary disk I/O and CPU overhead.
**Action:** Always prefer asynchronous file reads (`fs.promises.readFile`) to prevent event loop blocking. When dynamically rendering content that rarely changes (like static HTML with injected password hashes), implement a bounded in-memory cache to store the output. Ensure the cache key accounts for all variables affecting the output (filePath, password, adminpassword) and validate against file modification time (`mtimeMs`) to maintain freshness without needing to restart the server.
